# 多维表格（Duowei Table Pro）看板 / 日历 / 时间线 × 首页 结合方案

> 分析对象：`D:\data\obsidian_pls\duoweibiaoge`（duowei-table-pro 1.4.0）。
> 结论先行：**首页应“读视图配置、按视图语义渲染精简版”，写操作走多维表格插件暴露的小型 API**；不要在首页复刻整套视图，也不要直接改写 `.duowei`。

## 一、多维表格里与“任务 / 时间”相关的能力盘点

### 1. 文件与数据模型（`src/duowei/schema.ts`）

- `.duowei` 是纯 JSON：`fields[] / records[] / views[] / activeViewId / titleFieldId / taskHierarchy / meta.revision`。
- 记录：`values{fieldId: value}`、`notePath`（绑定笔记）、`createdAt/updatedAt`、`revision`。
- 字段类型：text / longText / number / checkbox / date / dateTime / singleSelect / multiSelect / rating / progress / noteLink / attachment / relation / lookup / rollup / formula / createdTime / updatedTime / autoNumber。
  - **静态文件里没有 formula / lookup / rollup 的计算结果**——首页离线读文件时拿不到这些值。
  - 单选值存的是 `option.id`，颜色是 `var(--color-xxx)`，可直接当 CSS 用。
- 视图公共配置 `DuoweiBaseViewConfig`：`filters[]`（21 种运算符，含 `isToday / isThisWeek / isThisMonth / before / after / isAnyOf …`）、`filterConjunction`、`sorts[]`、`colorRules[]`（条件着色）、`fieldOrder / hiddenFields`。
- `taskHierarchy.parentFieldId`：表级父子任务；日历 / 时间线会把父任务的时间范围**从叶子子任务推导**（`descendantPlanningDateRange`），并算完成进度（`taskProgress`）。
- 备份文件：`*.duoweibak`、`多维表格备份/`、`.自动备份.` 应跳过（`isEditableDuoweiFile`）；`source` 存在的是“库数据源表”，静态 `records` 为空，运行时才物化。

### 2. 看板 `viewCards.ts::renderKanban`

| 项 | 语义 |
| --- | --- |
| 分组字段 | `groupFieldId`；缺省取第一个 singleSelect / checkbox |
| 列 | singleSelect/multiSelect → **选项顺序**（含颜色）+「未分类」；checkbox → 已勾选 / 未勾选；其他离散值 → 去重后的值 |
| 卡片 | `titleFieldId` + `cardFieldIds` |
| 拖拽 | Pointer Events 拖到目标列 → `moveRecordToKanbanColumn` → `set_value(groupField, option.id)`，来源标记 `{type:"user", surface:"kanban"}` |
| 范围 | 只对 `visibleRecords`（已套用视图 filters / sorts / 搜索） |

### 3. 日历 `viewCalendarTimeline.ts::renderCalendar`

| 项 | 语义 |
| --- | --- |
| 日期字段 | `dateFieldId`（date / dateTime / createdTime / updatedTime / 结果为日期的 formula）；缺省取第一个日期类字段 |
| 显示模式 | `month` / `week` / `agenda`（列表，未来 30 天）/ `schedule`（小时日程，1/3/5/7 天，15/30/60 分钟槽） |
| 日程字段 | `scheduleStart/End/AllDayFieldId`；未配置时按字段名推断（开始 / 起始 / start… 与 结束 / 截止 / end…，见 `inferCalendarScheduleFields` + `timelineDateFieldRoleScore`），全天字段匹配 `/全天|all[\s_-]?day/` |
| 颜色 | `colorRules`（优先）> `colorFieldId`（单选继承选项色，其他值走 `planningStableColor` 稳定色板） |
| 层级 | `taskDisplayMode` flat / hierarchy / leaves / parents；父任务范围由子任务推导（`derived: true`） |
| 未排期 | 没有日期的记录归到“未排期”池，可拖到某天 |
| 写回 | 拖到某天 → `moveRecordToCalendarDate`；日程模式拖动 / 拉伸 → 改 start/end（`scheduleDateTimeValueForEdit` 保留原时区尾巴） |
| 时间解析 | `parseScheduleDateTimeValue`：`YYYY-MM-DD`、`YYYY-MM-DD HH:mm`、`YYYY-MM-DDTHH:mm[:ss][Z|±hh:mm]`，其余交给 `new Date()` |

### 4. 时间线 `renderTimeline`

- `startFieldId / endFieldId`（自动推断同上）、`scale` week / month / quarter、`anchorDate`；一条记录一根横条，`end < start` 时标记 `invalidEnd`。
- 拉伸左右边缘 → 改 start / end；拖动整条 → 平移。父任务同样推导范围，并显示子任务完成比例。

### 5. 仪表盘 `viewDashboard.ts` / `dashboardAnalytics.ts`

- widget：`number`（`fieldId` + `summary`: sum/avg/min/max/filled/unfilled/unique/checked，或记录数）、`bar` / `pie`（分组字段 + count/sum/avg）、`line`（按日/周/月分桶，可 7 期移动平均）；`sourceViewId` 决定统计范围（沿用那个视图的 filters）。

### 6. 已有的对外接口

- **Markdown 嵌入**（`embed.ts`）：`duowei` 代码块（`path / view / widget / type / group / aggregate / value / limit / fields`）或 `![[表.duowei#视图]]`、`![[表.duowei#图表:标题]]`。
  - **只会渲染两类东西**：仪表盘 / 单个图表，或把任意视图**当表格**渲染（套用该视图 filters / sorts，`recordsForViewLite`）。**看板 / 日历 / 时间线 / 画廊在嵌入里没有各自的形态**。
  - 嵌入自带排序 / 搜索 / 筛选，双击行打开源表（命中绑定笔记则打开笔记）。
- 命令：`快速添加记录到多维表格`（选表 → 输标题 → `create_record`）、`在当前多维表格新增记录`、插入视图 / 图表引用等。
- 写入通道：`TableRepository.commit(file, doc => MutationRequest)` → `MutationService`（操作：`set_value / clear_value / create_record / delete_record / bind_note / add_select_options …`；自动维护 `revision`、`updatedAt`、系统字段、触发自动化、按路径加写锁、落盘后 `publishCommitted` 让已打开的视图刷新）。**目前没有 `plugin.api` 之类的公开入口**，写入还受 Pro 授权 `requireProFeature("edit")` 约束。
- 已打开的视图对外部改动：`vault.on("modify")` 只标记 `knownFileStatDirty`，在下一次保存时走 `conflictMerge` 合并——首页若直接改文件，会进入冲突合并路径，不推荐。
- 打开到某个视图：`activeViewId` 存在文件里，切换靠视图私有方法 `switchViewById`；记录详情 `openRecordDetail(recordId)` 是公开方法（关联字段跳转就是 `leaf.openFile` → `view.revealRecord`）。

## 二、与首页结合的方式

### A. 现状（已实现）：跨表格“待办与日程”摘要

按字段名启发式识别日期 / 状态 / 完成勾选，分区列出逾期 / 今天 / 即将到期 / 进行中 / 最近更新。
局限：**不读视图配置**——用户在多维表格里精心配好的筛选、颜色、日程字段、任务层级，首页一概不知。

### B. 读侧：让首页组件“认视图”（推荐下一步，全部只读、零风险）

新增一个共享读取模块 `src/widgets/duoweiViews.ts`（一次实现，多个组件共用）：

```
readView(app, path, viewName) → {
  doc, view,
  records: 套用 view.filters (移植 matchesFilterLite) + sorts 后的记录,
  title(record), color(record)   // colorRules > colorFieldId > 选项色
  range(record)                  // 日历/时间线语义：start/end，含父任务由子任务推导
  columns()                      // 看板列：选项顺序 + 未分类
  complete(record)               // completionFieldFor 语义
}
```

基于它做四个首页组件（或作为「待办与日程」的四种模式）：

| 组件 | 数据来源 | 首页形态 | 交互 |
| --- | --- | --- | --- |
| **今日日程** | 某表的**日历视图** | 议程式：今天 / 明天 / 本周 分组，全天事件在前，时间段事件显示 `09:30–10:00`，左侧色条沿用视图配色；顶部小型 7 日条（每天一个点数） | 点击 → 打开表并定位记录；「＋」快速新增到今天（需 API，见 C） |
| **迷你看板** | 某表的**看板视图** | 横向列 = 选项顺序，每列显示计数 + 前 N 张卡（标题 + 2 个卡片字段） | 拖卡换列（需 API）；点击打开记录 |
| **里程碑 / 进度** | 某表的**时间线视图** | 未来 N 天开始或结束的记录；进行中的显示 `今天在 start~end 的位置` 进度条；父任务显示子任务完成 `3/5` | 点击打开 |
| **指标卡** | 仪表盘的 **number 类 widget** | 直接在首页渲染成 KPI 磁贴（count/sum/avg/…，按 `sourceViewId` 的筛选范围） | 点击打开仪表盘；bar/pie/line 继续用现成的 `duowei` 代码块嵌入（已支持） |

同时把现有「单表记录列表」升级为「按视图」：选视图后自动沿用其 filters / sorts / 颜色，用户不用在首页重复配置。

实现要点：
- 时间解析统一用 `parseScheduleDateTimeValue` 的规则（含 `T`/空格/时区尾巴），全天判断用 allDay 字段或“无时间部分”。
- 视图里的 `isToday / isThisWeek` 等相对运算符按本地日期评估；`isThisWeek` 以周一为起点（与插件一致）。
- 跳过 `source` 表（库数据源），提示改用嵌入。
- 文件按 `mtime` 缓存（已有 `loadDoc`），`.duowei` 变更已触发首页刷新。

### C. 写侧：给多维表格插件加一个小型公开 API（推荐，而不是首页直接写文件）

在 `duoweibiaoge/src/main.ts` 挂 `this.api`（约 80 行），首页通过 `app.plugins.plugins["duowei-table-pro"]?.api` 调用，缺失时组件自动降级为只读：

```ts
interface DuoweiPublicApi {
  version: 1;
  listTables(): TFile[];                                   // isEditableDuoweiFile 过滤
  readDocument(path): Promise<DuoweiDocument>;             // parseDuoweiDocument
  commit(path, operations: DuoweiOperation[], source?: { surface: string }): Promise<{ changed: boolean }>;
                                                           // → tableRepository.commit，自动 revision / 自动化 / 视图刷新 / 授权检查
  quickAdd(path, values: Record<fieldId, unknown>): Promise<string /* recordId */>;
  openRecord(path, recordId?, viewId?): Promise<void>;     // openFile → switchViewById → openRecordDetail
}
```

有了它，首页可以安全地做：看板拖卡换列（`set_value` 分组字段）、日程 / 待办勾选完成（`set_value` 完成字段）、今日日程「＋」新增（`create_record` 带日期）、时间线拖延一天（改 end）。所有语义（revision、updatedTime、自动化规则、Notion/飞书同步 tombstone、已打开视图的即时刷新、Pro 授权）都由多维表格插件自己保证。

不建议的做法：首页用 `vault.process` 直接改 `.duowei`——需要复刻 `MutationService` 的十几条规则，且与已打开的视图产生冲突合并。

过渡方案（API 未就绪前）：首页按钮触发现成命令 `duowei-table-pro:quick-add-record-to-duowei` / `add-record-to-current-duowei`，以及“打开表格”后由用户在视图里操作。

### D. 导航与入口

- 快捷入口支持 `表.duowei#视图名`：首页打开表后切到该视图（需 API 的 `openRecord(path, undefined, viewId)`；无 API 时退化为打开表，视图停留在 `activeViewId`）。
- 记录点击：有 `notePath` 开笔记，否则开表 + `openRecordDetail`。

### E. 视觉约定

- 颜色只用视图给的 `var(--color-*)` / 稳定色板，不在首页另起一套。
- 日程条目：`时间 · 标题 · 表名`，全天事件用圆点，跨天事件显示 `第 2/3 天`。
- 看板列头显示 `名称 · 计数`，超出 N 张时显示 `+M`。

## 三、落地顺序建议

1. **`duoweiViews.ts` 读取模块 + 「今日日程」+「迷你看板」（只读）** —— 价值最高、无风险。
2. **「指标卡」复用仪表盘 number widget**；「待办与日程」摘要增加“按视图筛选”选项。
3. **多维表格插件加 `api`** → 首页看板拖拽、勾选完成、快速新增（互动闭环）。
4. 「里程碑 / 进度」时间线组件；快捷入口 `#视图` 深链。

## 四、限制与风险

- 公式 / 查找 / 汇总字段在静态文件里没有值：涉及这些字段的筛选或标题只能在“嵌入”模式里由插件运行时计算。
- 库数据源表（`source`）静态无记录，只能嵌入。
- 写操作依赖 Pro 授权；API 内部应沿用 `requireProFeature("edit")`，首页据返回值提示。
- 日期时间字段可能带时区尾巴（`Z` / `+08:00`），首页展示时按本地时间换算，写回时保留原尾巴（`scheduleDateTimeValueForEdit` 的做法）。
- 大表（上千记录）解析已按 mtime 缓存；首页刷新是防抖的，不会造成明显卡顿。

## 五、更优雅的结合：把首页做成“宿主”，把语义留在源头（已实施，2026-09-14）

> 实施位置：Home Pages `src/api.ts` / `src/widgets/registry.ts`；多维表格 `src/duowei/homePages.ts`、`DuoweiTableView.activateView`、视图标签菜单「固定到首页」、`styles.css` 的 `mt-hp-*`。

上面 B/C 两层仍然是“首页去理解多维表格”。更优雅的形态是反过来：**首页只提供卡片宿主与统一的视觉框架，视图怎么读、怎么画、怎么改，由多维表格插件自己注册进来**。六条原则：

1. **一处配置，到处引用**：用户在多维表格里配好的视图（筛选、排序、颜色、日程字段、任务层级）就是唯一配置源；首页卡片只保存一个引用 `表.duowei#视图名`——与插件已有的嵌入链接语法完全一致，还能顺手支持 `#图表:标题`。
2. **语义归源插件**：首页不再猜日期字段、不再复刻筛选求值器；多维表格向首页注册一个“视图卡片”组件，内部复用自己的 `recordsForViewLite / planningColors / hierarchy / parseScheduleDateTimeValue`。
3. **交互同源**：卡片里的拖卡换列、勾选完成、＋新增，直接走插件的 `MutationService`（revision、自动化、外部同步、授权一并处理）；反向由 `publishCommitted` 的 ChangeSet 推送首页即时刷新，不靠文件轮询。
4. **形态跟随视图类型**：同一个组件，视图是日历就画议程，是看板就画迷你看板，是时间线就画里程碑条，是仪表盘就画 KPI/图表，是表格就画列表——用户不需要理解“首页有哪几种多维表格组件”。
5. **入口在源头**：在多维表格的视图标签右键菜单加「固定到首页」，一步完成；首页的「添加组件」里则用“表 → 视图”两级选择器（带视图类型图标）。
6. **渐进降级**：多维表格插件不在时，首页用自带的只读简版（现有的跨表摘要 / 记录列表）兜底，卡片引用不变。

### 双向 API 草案

**Home Pages 暴露（宿主侧，约 60 行）**

```ts
// app.plugins.plugins["home-pages"].api
interface HomePagesApi {
  version: 1;
  /** 第三方插件注册自己的首页组件；卸载时自动移除并在卡片上显示占位。 */
  registerWidget(definition: WidgetDefinition): () => void;
  /** 从源插件一键固定：kind + config，追加到当前页并打开配置弹窗（可选）。 */
  pinWidget(kind: string, config: Record<string, unknown>, options?: { title?: string; w?: number; h?: number }): Promise<void>;
  /** 让宿主重绘某类组件（源插件数据变化时调用）。 */
  refresh(kind?: string): void;
}
```

`WidgetDefinition` 就是现有 `src/widgets/types.ts` 里的接口（`render / renderSettings / defaultConfig / addHeaderAction / renderKpi …`），第三方拿到同一套 `ctx` 与 `ui/dom.ts` 的 KPI / 空状态 / 分段按钮，视觉自然一致。

**多维表格暴露 / 注册（源插件侧，约 200 行）**

```ts
// 注册到首页的组件
homePages.registerWidget({
  kind: "duowei-view",
  name: "多维表格视图",
  defaultConfig: () => ({ ref: "" }),                // "表.duowei#视图名" 或 "#图表:标题"
  render(body, ctx) {
    const { file, view } = resolveRef(ctx.config.ref);
    switch (view.type) {
      case "calendar":  return renderCompactAgenda(body, ctx, file, view);   // 今天/明天/本周
      case "kanban":    return renderCompactKanban(body, ctx, file, view);   // 列计数 + 前 N 张卡，可拖
      case "timeline":  return renderCompactMilestones(body, ctx, file, view);
      case "dashboard": return renderCompactDashboard(body, ctx, file, view); // number→KPI，图表→现有 embed
      default:          return renderCompactList(body, ctx, file, view);     // 套视图 filters/sorts
    }
  },
  renderSettings: (el, ctx) => tableViewPicker(el, ctx)                     // 表 → 视图 两级选择
});

// 同时对外提供数据/写入接口，供不想走注册的宿主（或首页兜底逻辑）使用
plugin.api = {
  version: 1,
  listTables(), readDocument(path), recordsForView(path, viewName),
  commit(path, operations, source), quickAdd(path, values),
  openRecord(path, recordId?, viewId?),
  onChange(path, callback): () => void                                        // ChangeSet 订阅
};
```

视图标签右键 → 「固定到首页」= `homePages.pinWidget("duowei-view", { ref: `${file.path}#${view.name}` }, { title: view.name })`。

### 与前一方案的差别

| | 首页自己理解多维表格（B/C） | 宿主 + 源插件注册（本节） |
| --- | --- | --- |
| 组件数量 | 4 个（日程 / 看板 / 里程碑 / 指标） | 1 个「多维表格视图」，形态随视图类型 |
| 字段 / 筛选 / 颜色 | 首页重新实现一遍求值器与推断 | 直接复用插件代码，永远与表内一致 |
| 写操作 | 需要额外 `api.commit` | 组件本身就在插件里，直接调 `MutationService` |
| 刷新 | 文件事件 + 防抖 | ChangeSet 推送，毫秒级 |
| 新视图类型 / 新字段类型 | 首页要跟着改 | 插件升级即生效 |
| 无插件时 | — | 首页自带只读简版兜底 |

同样的宿主 API 也让 Mobile Ink Annotation（「今日待复习 / 收件箱」卡）和 WeChat2Ob（「最近消息」卡）各自注册自己的首页组件；首页里现有的三张卡退为兜底实现。

### 落地步骤（建议）

1. Home Pages：把 `registry` 改成可运行时注册（`registerWidget/unregister`），暴露 `api`，卡片遇到未注册 kind 时显示“等待插件 X”占位而不是丢弃配置。
2. 多维表格：加 `api` + `duowei-view` 组件（先做 calendar→议程、kanban→迷你看板、dashboard→KPI 三种紧凑渲染，其余回落为列表）+ 视图标签「固定到首页」。
3. Ink / WeChat2Ob 视时间跟进注册；首页保留兜底卡片。
